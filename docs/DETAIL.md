# 消费者洞察工作台

把一次消费者调研最费时的四件事——判断该问什么、写问卷、备分析框架、算样本怎么分——变成一次填表。

## 它解决什么

项目启动时，问卷常常是从上一份里改的，模块该有哪些靠记忆，分析框架等数据回来才想，抽样配额靠经验估。结果是：问了的不分析、要分析的没问、和代理对不上口径。

这个插件把品牌追踪与用户满意度两类调研的标准做法沉淀成「标准件」，再按项目参数实例化，生成一套能直接发给代理、带进会议的文件。

## 怎么用

1. 左侧栏点「消费者洞察」（与「插件」「定时任务」同级）。
2. 填项目目标（写清要支撑什么决策）、调研类型、品类、主品牌、竞品、目标人群、样本量。
3. 点「生成方案」。右侧按「简报 / 问卷 / 分析框架 / 抽样」四个页签查看，并给出自动体检结果。
4. 点「保存到电脑」，生成到输出目录（默认 `~/Documents/消费者洞察`，点右上角目录名可改）。
5. 要改：回左侧改参数重新生成；或在对话里让 Agent 调用 `insight_generate` 改参数重生成。

## 生成什么

| 文件 | 内容 |
| --- | --- |
| `00-项目简报.md` | 目标、业务决策、研究问题、指标、样本、交付清单 |
| `01-研究设计.md` | 筛选逻辑、样本设计、质控、排期、风险与应对 |
| `02-问卷.docx` | Word 问卷：模块标题、题号、题型、选项、base、跳转、编程说明，网格题用表格 |
| `02-问卷.md` / `.csv` | 同内容的可检索版与编程用平面表 |
| `03-分析框架.xlsx` | 4 张表：追溯表、指标定义、交叉表与分组、图表清单 |
| `03-分析框架.md` | 同内容可读版，含高级分析、报告大纲、数据交付规范 |
| `04-抽样与配额.md` | 精度、三种分配方案、完整配额、加权、接触量、成本、排期、调整规则 |
| `04-配额表.csv` | 24 个交叉格，可直接贴进 Excel |
| `05-码表.csv` | 变量名、编码、base、缺失值 |
| `06-执行与QC清单.md` | 编程前、试访、正式访问、数据回收、交付前 |
| `project.json` | 项目参数与生成结果，供再次编辑 |

## 抽样模块

给出的是「样本怎么分」的建议方案，而不只是一个数字：

- 精度表：n 与误差、有效样本（95% 置信、p=0.5、设计效应 1.2）。
- 三种方案：A 比例分配、B 分组等分、C 比例 + 保底（推荐）。
- 完整配额：城市级别 × 性别 × 年龄，含样本占比、总体占比、设计权重。
- 接触量与成本：需接触人数、总访谈时长、田野天数、总成本。
- 排期与调整规则：某格招不满、低线贵、incidence 过低、要检测更小差异时怎么改。

## 三条限制

1. 生成稿是专业骨架 + 项目定制，**投放前必须由研究员审校**，并与客户确认品牌、渠道、价盘口径。
2. 不生成「行业平均」「竞品实测值」等基准数据；需要时在文件里标注待补来源。
3. 配额、成本、排期是建议值，最终以抽样框与代理报价为准。

## 数据放在哪

- 表单草稿与项目索引：`~/.dsh/consumer-insight/state.json`。
- 生成的文件：输出目录，默认 `~/Documents/消费者洞察`；可在面板右上角更改，或用环境变量 `DSH_CONSUMER_INSIGHT_DIR` 指定。
- 生成过程不联网、不调用模型、不上传内容。

## 对话里怎么用

- 「用品牌追踪的方法，给即饮咖啡 A 品牌做一份 18-30 岁人群的问卷」→ 调 `insight_generate`。
- 「品牌追踪标准件都包含哪些模块」→ 调 `insight_playbook`。
- 「上次那个满意度项目参数是什么」→ 调 `insight_project`。
